===== ASSEMBLY SYNTAX =====

==== GENERAL SYNTAX ==== 

All instructions sans headers, flags, and macro definitions, end in a semicolon (;).

==== TOKEN TYPES ====

There are a few types of arguments that the assembler can recognize, each with its own prefix character:

    Instructions do not have a prefix character.

    (.) Headers

        These are for telling the assembler where to look for specific things. There are currently three in use:
        .macros : Used for defining the macro section. This goes before all other headers.
        .start  : This is the entry point for the program. Code will begin execution immediately after this line. Goes directly after the .macros header.
        .end    : Ends the program. The compiler will automatically convert it into a HLT operation if nothing else is specified. Last line in the program.

    ($) Flags
        
        These are defined by the user and intended for organizing routines and flow control. Initiating character is a $, and ends at the next whitespace character.
        Flags can be used as immediate arguments in JMP operations, as the assembler will convert the value directly to the line on which the flag is placed. 

    (_) Macros

        Macros are used in a similar way to a subroutine in functional programming, as a way of abstracting repeated and/or tedious code. Macros are defined as such:
        _macroName %arg1, %arg2, ..., %argN:

        and followed by the reserved word _end at the end of the declaration.

        Within the macro declaration, the user can use any number of arguments as provided to the macro.
        All macro arguments in the definition must be prefaced with a (%) character.
        All other instructions operate as normal within a macro.

        The assembler will copy-paste the definition within a macro to wherever it is called.

===== SUBCOUNTER STEPS FOR MULTI-CYCLE INSTRUCTIONS (all of them) =====

Each instruction starts with the same pre-cycle, preparing the instruction decoder for the current instruction and setting the PC to the next value for the next instruction.
As any given instruction finishes executing, it sets the subcounter back to zero, resetting the process on the recently updated PC.

Next, it fetches the I-value from the instruction (see specs.txt for info) and adjusts the program counter as necessary.

==== PRE-CYCLE ====

RAM[PC] -> IR,      SC+1 -> SC
RAM[PC+1] -> OP1    SC+1 -> SC      ; if necessary. determined by I-value
RAM[PC+2] -> OP2    SC+1 -> SC      ; if necessary. determined by I-value

PC+<deterministic value based on, but not equal to, the I-value> -> PC

==== DUTY CYCLE ====

This part of any instruction changes, per instruction.
Observe the list below for each instruction's specific operations

=== NOP === [000 000]
(Nothing. No operation.)

=== HLT === [000 111]
(Nothing. No operation.)



=== ADD === [001 000]
R[A] + R[B] // OPB -> S

=== SUB === [001 001]
R[A] - R[B] // OPB -> S

=== INC === [001 010]
R[A] + 1 -> S

=== DEC === [001 011]
R[A] - 1 -> S



=== AND === [010 000]
R[A] & R[B] // OPB -> S

=== ORR === [010 001]
R[A] | R[B] // OPB -> S

=== NOT === [010 010]
~ R[A] -> S

=== XOR === [010 011]
R[A] ^ R[B] // OPB -> S



=== LSL === [011 000]
R[A] << 1 -> S

=== LSR === [011 001]
R[A] >> 1 -> S

=== ASL === [011 010]
R[A] A<< 1 -> S

=== ASR === [011 011]
R[A] A>> 1 -> S



=== JMP === [100 000]
R[A] // OPA -> PC

=== JZR === [100 001]
R[A] // OPA -> PC [only if F[0] is high.]

=== JEV === [100 010]
R[A] // OPA -> PC [only if F[1] is high.]

=== JOF === [100 011]
R[A] // OPA -> PC [only if F[2] is high.]

=== JNG === [100 100]
R[A] // OPA -> PC [only if F[3] is high.]

=== JSR === [100 110]
SP + 1 -> SP
PC -> M[SP]
R[A] // OPA -> PC

=== RET === [100 111]
M[SP] -> PC
SP - 1 -> SP



=== PSH === [101 000]
SP + 1 -> SP
R[A] // OPA -> M[SP]

=== POP === [101 001]
M[SP] -> R[A]
SP - 1 -> SP

=== TOP === [101 010]
M[SP] -> R[A]



=== MOV === [110 000]
R[B] -> R[A]

=== LDA === [110 001]
M[R[B] // OPB] -> R[A]

=== LDI === [110 010]
R[B] // OPB -> R[A]

=== STR === [110 011]
R[B] // OPB -> M[R[A]]

=== SWP === [110 100]
R[A] -> W
R[B] -> R[A]
W -> R[B]



=== RDX === [111 000]
X -> R[A]

=== RDY === [111 001]
Y -> R[A]

=== WRZ === [111 010]
R[A] // OPA -> Z

=== WRW === [111 011]
R[A] // OPA -> W


==== POST CYCLE ====

0x0 -> SC                           ; to reset subcounter and start execution of next instruction
                                    ; MAX SUBCOUNTER TICKS REQUIRED : 7ish.
